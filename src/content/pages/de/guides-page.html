Konzepte und Komponentenverhalten verstehen.

Von den Grundprinzipien bis zu Lifecycle, Props, Slots und Eltern-Kind-Kommunikation.

Diese Seite bündelt die zentrale Arbeitsweise von KoppaJS: Komponenten als Custom Elements, Registrierung über Core.take(), reaktiver State, die Template-Sprache und das Zusammenspiel von Props, Events und Hooks.

Kurzform

Core.take(appView, "app-view");
Core();

return {
  state: { count: 0 },
  methods: {
    increment() {
      this.count++;
    },
  },
};

Grundkonzepte

Wie KoppaJS funktioniert.

Komponenten als Custom Elements

Jede Komponente wird als natives Custom Element registriert. Der Tag-Name muss wegen des Web-Components-Standards immer einen Bindestrich enthalten, etwa <app-view>.

Registrieren, dann booten

Mit Core.take() registrierst du Komponenten, Plugins oder Module. Erst Core() startet das Framework und mountet registrierte Elemente im DOM.

Reaktive Proxys

Der State wird automatisch in einen Proxy gewrappt. Jede Mutation kann ein Re-Rendering auslösen, ohne dass du DOM-Patches manuell schreiben musst.

Komponenten, Plugins und Module

Komponenten rendern UI. Plugins liefern appweite Dienste wie Stores oder Router-Zugriffe über $take("name"). Module erweitern Komponenten oder Elemente mit zusätzlicher Laufzeitlogik. 

import { Core } from "@koppajs/koppajs-core";
import appView from "./app-view.kpa";
import storePlugin from "./store-plugin";
import routerModule from "./router-module";

Core.take(storePlugin);
Core.take(routerModule);
Core.take(appView, "app-view");
Core();
created() {
  const store = $take("store");
  store.loadUser();
},

mounted() {
  this.$router?.navigate("/dashboard");
}

Lebenszyklus einer KoppaJS-App

1. main.ts wird geladen und importiert .kpa-Dateien.
2. Core.take(...) registriert Komponenten und optionale Erweiterungen.
3. Core() startet die App und findet Custom Elements im DOM.
4. Script, Props und reaktiver State werden vorbereitet, danach feuert created().
5. Das Template wird verarbeitet, Events werden gebunden, der DOM wird eingesetzt und mounted() läuft.
6. Weitere State-Änderungen lösen automatische Updates aus.
