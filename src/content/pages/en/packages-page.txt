      <section id="rollen" class="docs-section-card docs-section-anchor">
        <p class="docs-eyebrow">Roll</p>
        <h2 class="docs-section-title">Each package covers a clear area of ​​responsibility.</h2>
        <div class="docs-grid-2">
          <article class="docs-mini-card">
            <h3><code>@koppajs/koppajs-core</code></h3>
            <p class="docs-text">Registers components via <code>Core.take()</code>, boots the application with <code>Core()</code>, manages reactive state and keeps DOM reconciliation, hooks, props and events together.</p>
          </article>

          <article class="docs-mini-card">
            <h3><code>@koppajs/koppajs-vite-plugin</code></h3>
            <p class="docs-text">Transforms <code>.kpa</code> single-file components into JavaScript, integrates TypeScript, and ensures that Vite-HMR and Build work with the same component form.</p>
          </article>

          <article class="docs-mini-card">
            <h3><code>create-koppajs</code></h3>
            <p class="docs-text">Delivers the fastest starting point, including project structure, Vite configuration and starter interface.</p>
          </article>

          <article class="docs-mini-card">
            <h3><code>@koppajs/koppajs-router</code></h3>
            <p class="docs-text">Not part of the minimal installation, but useful for documentary websites or real apps with multiple views. It solves routes, keeps links active and renders pages in the outlet.</p>
          </article>
        </div>
      </section>

      <section id="registrierung" class="docs-section-card docs-section-anchor">
        <p class="docs-eyebrow">registration</p>
        <h2 class="docs-section-title">Components, plugins and modules all end up in the same startup sequence.</h2>
        <article class="docs-mini-card">
          <pre class="docs-code"><code>import { Core } from "@koppajs/koppajs-core";
import appView from "./app-view.kpa";
import storePlugin from "./store-plugin";
import routerModule from "./router-module";

Core.take(storePlugin);
Core.take(routerModule);
Core.take(appView, "app-view");

Core();</code></pre>
          <ul class="docs-list">
            <li><code>Core.take(component, "tag-name")</code> registers a component as a custom element.</li>
            <li><code>Core.take(plugin)</code> registers an app-wide service for <code>$take("name")</code>.</li>
            <li><code>Core.take(module)</code> activates additional runtime functionality, for example under <code>this.$router</code>.</li>
          </ul>
        </article>
      </section>

      <section id="einsatz" class="docs-section-card docs-section-anchor">
        <p class="docs-eyebrow">When which package?</p>
        <h2 class="docs-section-title">A pragmatic decision-making framework for new projects.</h2>
        <div class="docs-grid-2">
          <article class="docs-mini-card">
            <h3>Duty</h3>
            <ul class="docs-list">
              <li>You need <code>@koppajs/koppajs-core</code> in every KoppaJS app.</li>
              <li>You need <code>@koppajs/koppajs-vite-plugin</code> as soon as you use <code>.kpa</code> files with Vite.</li>
            </ul>
          </article>

          <article class="docs-mini-card">
            <h3>Optional but practical</h3>
            <ul class="docs-list">
              <li>You use <code>create-koppajs</code> for quick project starts or starter updates.</li>
              <li>You add <code>@koppajs/koppajs-router</code> if views, navigation and fallbacks should be modeled explicitly.</li>
            </ul>
          </article>
        </div>

        <div class="docs-note">The official user documentation describes the core packages. Additional packages such as routers, stores or analytics are attached to the same basic architecture as plugins or modules.</div>
      </section>
